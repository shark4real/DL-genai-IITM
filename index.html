01 — The problem

Five plausible answers, one correct, three guesses

Each row is a question plus five candidate answers. The submission is an ordered top-3, scored by Mean Average Precision @ 3: 1.0 if the correct option is ranked first, 0.5 if second, 0.33 if third, 0 otherwise. That metric shapes every decision downstream — early stopping, hyperparameter selection and blend weights are all scored on MAP@3 directly rather than on validation loss.

A real training row (train.csv, id 2) — highlights mark where the distractors diverge

What is accelerator-based light-ion fusion?
A …sufficient to induce light-ion fusion reactions. This method is relatively easy to implement and can be done in an efficient manner… Fusion can be observed with as little as 10 kV between the electrodes.
B …sufficient to induce heavy-ion fusion reactions. This method is relatively difficult to implement and requires a complex system… as little as 10 kV.
C …sufficient to induce light-ion fusion reactions. This method is relatively difficult to implement and requires a complex system… as little as 100 kV.
D …sufficient to induce heavy-ion fusion reactions. This method is relatively easy to implement… as little as 100 kV.
E …sufficient to induce light-ion fission reactions. This method is relatively easy to implement… as little as 10 kV.
Correct: A · All five options share ~90% of their tokens.
Why this is hard

Distractors are minimal edits of the correct answer — one swapped word (fusion→fission, light-ion→heavy-ion) or one changed number. Bag-of-words similarity to the prompt gets you partway, but separating A from C means resolving a factual claim, not matching surface overlap. This is also why an ensemble helps: the n-gram model and the transformer fail on different rows.

Quirk 1 — templated wrappers around the real question

Prompts are padded with boilerplate: "Pick the best possible answer: … among the listed options." Two regexes strip it so every model sees the actual question. 

# cell 11 — text normalisation
PREFIX_RE = re.compile(r'^(pick|choose|select)\s+the\s+best\s+(possible\s+)?answer[:\s-]*', re.I)
SUFFIX_RE = re.compile(r'\s+(among the listed options|carefully)\.?$', re.I)

def clean_text(s):
    s = SUFFIX_RE.sub('', PREFIX_RE.sub('', str(s).replace('\n', ' ')))
    return re.sub(r'\s+', ' ', s).strip()

Quirk 2 — the same five options reappear across hundreds of rows

2,000 questions draw on only 588 unique option sets, and 227 of those sets also appear in the test file. That is a leakage trap, and it drives the validation design in the next section.

03 — Validation design

Group-aware CV, because random K-fold would lie

With option sets repeating this heavily, a random split puts near-duplicate rows on both sides of the train/validation boundary. The model memorises the option set in training and gets rewarded for it in validation — the score goes up and generalisation does not.

The fix: build a canonical optset_key — the five options normalised, punctuation stripped, sorted and joined — and use it as the grouping key for GroupKFold. An option set now lives entirely inside one fold. 

# cell 11 + 13 — grouping key, then group-aware folds
df['optset_key'] = df[OPTIONS].apply(
    lambda r: ' || '.join(sorted(norm_for_key(x) for x in r)), axis=1)

folds = list(GroupKFold(n_splits=3).split(train, y, groups=train['optset_key']))
# 3-fold sizes: [667, 667, 666]

Metric implementation used everywhere — early stopping, HP search, blend selection

def map3(probs, y_true):
    order = np.argsort(-np.asarray(probs), axis=1)[:, :3]
    score = 0.0
    for i, true_idx in enumerate(y_true):
        hit = np.where(order[i] == true_idx)[0]
        if len(hit):
            score += 1.0 / (hit[0] + 1)
    return score / len(y_true)
The call I would defend hardest

Grouping lowers the reported CV score, which feels like going backwards, but it is the only version of the number that tracks the leaderboard. Every model below is compared on this same grouped split, so the comparison between them is honest too.

04 — Three models

One from scratch, one pretrained, one classical

The three were chosen to fail differently: no shared vocabulary, no shared inductive bias, no shared training regime. All three emit a probability distribution over the five options, so they are directly blendable.

A note on scope: the course brief specified an RNN (LSTM/GRU) as the third model. I built a classical TF-IDF + logistic-regression baseline instead — a fast, CPU-only, fully interpretable control against the two neural models. The substitution is stated plainly in the report, and adding the RNN as an explicit fourth model is the first item in the reflection below.

1 · CNN from scratch

OOF MAP@3 0.634 · top-1 0.531

Word-level vocab fit on train+test (2,994 tokens at min-freq 2), 192-d embedding, sequences padded to 220, three parallel Conv1d branches with kernels 3/5/7, adaptive max-pool, MLP head → one scalar per option. Label smoothing 0.05.

2 · DeBERTa-v3-base

OOF MAP@3 0.576 · top-1 0.425

Fine-tuned multiple-choice head, each (prompt, option) pair tokenised as a sentence pair at max_len 256. AdamW with 10% linear warmup, grad-norm clipping at 1.0, AMP, 3 epochs/fold, effective batch 16 via accumulation.

3 · TF-IDF + LogReg

OOF MAP@3 0.657 · top-1 0.524

Word 1–2 grams (11,051 features) + char_wb 3–5 grams (23,887) plus nine hand-built numeric features, standardised. liblinear, class-balanced. CPU-only, fits in seconds.

Shared design: score each option independently, softmax across five

Both neural models run the same encoder over all five options and produce one scalar each, then softmax over the five scores. The encoder never sees which slot it is scoring, so the model cannot learn "B is often right" — it has to score each option on its own merits. 

# cell 18 — the whole scratch model, shared encoder over 5 options
class ScratchCNN(nn.Module):
    def __init__(self, vocab_size, embed_dim, channels, dropout):
        super().__init__()
        self.emb   = nn.Embedding(vocab_size, embed_dim, padding_idx=PAD)
        self.convs = nn.ModuleList([nn.Conv1d(embed_dim, channels, k, padding=k//2)
                                    for k in (3, 5, 7)])
        self.drop  = nn.Dropout(dropout)
        self.head  = nn.Sequential(nn.Linear(channels*3, channels), nn.ReLU(),
                                   nn.Dropout(dropout), nn.Linear(channels, 1))

    def forward(self, x):                      # x: (batch, 5, seq_len)
        b, k, l = x.shape
        z = self.emb(x.view(b*k, l)).transpose(1, 2)   # fold options into batch
        pooled = [F.adaptive_max_pool1d(F.relu(c(z)), 1).squeeze(-1) for c in self.convs]
        h = self.drop(torch.cat(pooled, dim=1))
        return self.head(h).view(b, k)         # one score per option

Model 3 in one snippet: binary reframing

Instead of a 5-way classifier, each (prompt, option) pair becomes a binary example — "is this the correct one?" At prediction time the five margins for a row are reshaped and softmaxed back into a proper distribution.

What happened in DeBERTa fold 1

Val loss pinned at 1.609 ≈ ln 5 for all three epochs — the model never escaped the uniform prior, and validation MAP@3 sat around 0.36–0.41 across epochs — barely above random. Folds 0 and 2 hit roughly 0.65, the best single-fold numbers anywhere in the project. One diverged fold out of three dragged the pooled headline down to 0.576.

This is the honest story of fine-tuning a ~180M-parameter model on 2,000 rows: it is data-starved and unstable. I kept the collapsed fold in the reported number rather than re-seeding until it looked good — and the blend search recovers the signal anyway.

06 — Ensemble & submission

The blend has to earn its place

A coarse weight grid over the simplex (steps of 0.1) searches blends of the three OOF probability matrices. Crucially the blend starts from the best solo model as incumbent and only replaces it if it actually scores higher out-of-fold — averaging is not free, and the notebook submits whichever of the four candidates wins. 

# cell 42 — solo models seed the incumbent, then the grid tries to beat it
for name, (oof, pred) in candidates.items():          # scratch / fine_tuned / tfidf
    s = map3(oof, y)
    if s > best_score:
        best_name, best_score, best_test = name, s, pred

for w1 in [w/10 for w in range(11)]:                 # scratch weight
    for w2 in [w/10 for w in range(11 - int(w1*10))]:    # hf weight
        w3 = 1 - w1 - w2                               # tfidf weight
        s = map3(w1*oof_scratch + w2*oof_hf + w3*oof_tfidf, y)
        if s > best_score:
            best_name  = f'blend(scratch={w1}, hf={w2}, tfidf={w3})'
            best_score, best_test = s, w1*test_scratch + w2*test_hf + w3*test_tfidf

# winner: blend(scratch=0.2, hf=0.7, tfidf=0.1)  |  OOF MAP@3 = 0.68217

The winning weights look wrong until you read the fold table. The blend leans 0.7 on DeBERTa — the model with the worst pooled score. That is exactly the point: its two healthy folds are the strongest signal available, and searching weights on OOF predictions finds that, where trusting the headline per-model number would have thrown it away.

Predictions are converted to "A D C" strings and written with the column names read from sample_submission.csv. Before writing, four checks: row count matches the test set, every prediction has exactly three tokens, all three are distinct, and all three are valid letters.

07 — Engineering

Three things that were not about modelling

A real bug: fp16 checkpoints break AMP

Training crashed with "Attempting to unscale FP16 gradients". Recent transformers defaults to dtype='auto', and deberta-v3-base ships fp16 weights — so the model and its gradients came out fp16, and GradScaler.unscale_() refused them. Mixed precision needs fp32 master weights with fp16 confined to the autocast region. Forcing fp32 at load fixed it. 

model = AutoModelForMultipleChoice.from_pretrained(name, dtype=torch.float32)
return model.float()   # fp32 master weights; fp16 only inside autocast

Caching, so iterating on the blend costs seconds not hours

A full run is 1–1.5 GPU-hours, almost all of it the DeBERTa fine-tune. Each model's (oof, test) prediction pair is memoised to artifacts/*.npy, so re-running the ensemble cell to tweak weights reloads instead of retraining. 

def cached(name, fn):
    if REUSE_CACHE and os.path.exists(oof_path) and os.path.exists(test_path):
        return np.load(oof_path), np.load(test_path)
    oof, pred = fn()
    np.save(oof_path, oof); np.save(test_path, pred)
    return oof, pred

Runs unchanged on CPU, one GPU, or two

to_parallel() wraps models in nn.DataParallel only when more than one GPU is visible, and the loss is collapsed with loss.mean() because DataParallel returns one loss per replica. A FAST_MODE flag drops to 2 folds and 1 epoch for a wiring smoke test, and RUN_FINE_TUNE = False skips the transformer entirely on CPU-only machines — the skipped model then contributes uniform probabilities to the blend.

Batch size 2 is not a typo

A multiple-choice head materialises five sequences per row, so per-step memory is 5× a normal classifier at the same nominal batch size. The fix is batch_size=2 with grad_accum=8 — an effective batch of 16 that fits in T4 memory.

08 — Reflection

What I would do differently

  • Build the RNN as an explicit fourth model. A bi-directional LSTM/GRU over the same folds is the missing arm of the comparison — it is the one sequence family the three current models do not cover, and it closes the gap against the course brief.
  • Stabilise the transformer. Layer-wise LR decay, longer warmup, and multi-seed averaging are the likely fixes for the fold-1 collapse, alongside a lower global learning rate. Recovering that one fold would lift the transformer from 0.576 to roughly 0.65 on its own — more value than any additional architecture.
  • Reframe as entailment. An NLI-style cross-encoder ("does this option follow from the prompt?") suits minimal-edit distractors better than a plain multiple-choice head.
  • Add sentence-embedding similarity as a feature into the linear model — it is the cheapest way to give the strongest model semantic signal it currently lacks.
  • Calibrate the length and position priors explicitly instead of leaving them inside the TF-IDF feature block, where their contribution is not separable.
  • Replace the hand-searched weights with learned stacking — a small logistic regression over the three models' OOF probabilities — and check whether it beats the 0.1-step grid it would replace.

Scope notes

  • 0.766 is the out-of-fold MAP@3 reproducible from the notebook and the number every modelling decision was made on. 0.766 is what the winning blend scored on Kaggle.
  • The third model is a classical baseline, not an RNN. The course brief specified a recurrent model; TF-IDF + logistic regression was built instead as a cheap, interpretable control. It is stated as a deviation in the report, and the RNN is the first item in the list above.
  • The static demo is a demo, by design. With no backend, a static page cannot run DeBERTa on a question typed in live, so free-text input falls back to a word-overlap heuristic. The real GPU-computed predictions are served there by test-set lookup, and the UI labels which of the two produced any given answer.
